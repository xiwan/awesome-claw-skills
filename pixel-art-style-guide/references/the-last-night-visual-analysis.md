## 从数据里读出的 5 条硬规则

### 1. 画幅比 2.53 : 1（比 21:9 更宽）

原始文件尺寸实测：1024×405、600×237、640×249 → **2.53–2.57 : 1**。
比常说的 21:9（2.33）更宽，接近 CinemaScope 2.39–2.55。
（表中 02 和 07 是裁图，不参与画幅比统计。）

- 做法：正常渲染 16:9，再用上下黑边裁到 ~2.53
- 换算：1920 宽 → 有效高度 **759px**，上下各切 160px

### 2. 亮度只有两种合法分布，不许"中间态"

| 模式 | 近黑占比 | 中位亮度 | 平均饱和 | 用在哪 |
|------|---------|---------|---------|--------|
| **深夜/室内模式** | 24–77% | 0.08–0.24 | 0.37–0.69 | 绝大多数镜头（01-05、07、两段动图） |
| **雾抬黑场模式** | ≈0% | 0.39–0.52 | 0.26–0.29 | 大雾/远景（06、08） |

关键：**过曝像素永远 < 5%，多数 < 1%**。霓虹再亮也不糊成白块，
bloom 是往外溢，不是把像素推到 255。

最常见的错误是渲染出"中位亮度 0.3 / 近黑 5% / 饱和 0.4"的中庸画面——两种模式都不是，风格直接消失。

### 3. 一帧只有一个主导色相 + 一个被压住的强调色

每张参考图里某个 30° 色相带独占饱和像素的 **49%–98%**（室内枪战 98%，近乎单色）。
次色相带压在 **≤17%**：01 是青蓝主 + 琥珀/粉点，05 是橙主 + 绿招牌 13%。

实操：给每个场景在配置里写死一个 30° 色相带，所有光源色从这个带里取；
第二色只允许出现在**单个物件**上（一块招牌、一盏警示灯）。

### 4. 高光颜色是一份很短的清单

各图最亮聚类（V>0.75 且 S>0.3，量化到 32 级）：

| 光源类型 | 实测色 | 出现场景 |
|---------|--------|---------|
| 钠灯橙 | `#C06020` `#E08040` `#E0A040` | 01 03 05 07 anim-01 |
| 灯泡奶油 | `#C0A060` `#C0A080` `#E0A080` | 02 04 |
| 霓虹青 | `#00A0C0` `#40A0C0` `#4080C0` | 01 02 06 |
| 警示红 / 灯笼 | `#C02020` `#E04040` `#E06040` | anim-01 anim-02 |
| 招牌绿 | `#80C080` `#A0E080` | 08 |

注意：**没有一个高光聚类到达纯白**，最亮通道基本停在 `0xE0`。
给光源设色时别用白光，每盏灯都要有明确色相。

### 5. 饱和度与雾量成反比

深夜近景 0.47–0.69 ↔ 大雾远景 0.26–0.29。
雾在数值上同时做两件事：抬黑场 + 去饱和。
所以远景不是"变暗"，而是"变灰 + 变亮"——这跟传统像素画远景压暗的直觉相反。

## 构图套路（目测，非实测）

8 张图里反复出现的习惯：

- **底部 20–35% 是湿地/水面**：垂直拉长的倒影 + 大颗失焦 bokeh 圆斑（02 最典型）
- **边缘前景遮挡物**：左右边缘放一条完全虚化的暗色竖块（07 左侧、04 左侧人影）
- **人群 = 3 层以上剪影**：只有轮廓光，五官永远不可读，靠密度制造城市感（05 06 anim-01）
- **招牌就是光源**：唯一出现高饱和纯色相的地方，字形是伪中日文
- **体积光必须有介质**：门缝/单灯射出的 god rays 一定穿过雾或雨（01 04 07）
- **植被压科技**：藤蔓、榕树盖在机械与招牌上（02 04 05）——后赛博朋克，不是废土
- **角色占比小**：宽景里角色约占画面高度 10%（02 05 06），近景可到 30%+（01）

## 动图能看出、静图看不出的

`anim-01` / `anim-02` 是 ~2 秒、33fps 的捕获（63 / 72 帧）：

- 摄像机**一直在动**（缓慢平移/推拉），没有静止帧
- 雾、雨、火星、招牌闪烁各走**独立的连续时间轴**，不是 12fps 步进
- 这两段是全套素材里最暗的（近黑 77%，中位亮度 0.08）——**动起来的画面比静帧更暗**，
  因为运动本身在提供信息，不需要靠亮度撑读性
- 结论：**sprite 可以是 12fps 步进的，但摄像机、光照、粒子、后处理必须跑满帧率**。
  这是 "low-fi assets, hi-fi rendering" 在时间轴上的体现

## 用 analyze.py 验收自己的画面

脚本零第三方依赖（纯标准库），只读 24/32-bit BMP：

```bash
# 等比缩放很重要，否则画幅比判定失效
sips -s format bmp --resampleWidth 300 my_render.png --out /tmp/my_render.bmp
python3 references/the-last-night/analyze.py /tmp/my_render.bmp
```

脚本自动判定属于哪种亮度模式，并逐条给 PASS / WARN：

- [ ] 画幅比 2.4–2.6 : 1
- [ ] 过曝像素 < 5%
- [ ] 单一 30° 色相带 ≥ 45% 饱和像素
- [ ] 次色相带 ≤ 20%
- [ ] 最亮聚类带明确色相（非纯白）
- [ ] 深夜模式：近黑 20–80% 且平均饱和 ≥ 0.35
- [ ] 雾模式：近黑 ≈0%、中位亮度 0.35–0.55、平均饱和 ≤ 0.30

十张参考图跑下来全部 PASS（02 / 07 因为是裁图，画幅比一项 WARN 属预期）。
