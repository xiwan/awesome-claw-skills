# 选项与分支

## 选项是什么

交互（interactive）= 用户与内容双向影响。游戏区别于小说/话剧/电影的核心要素，
在剧本层面的落点就是**选项**。

选项 = 为"玩家脑中的问题"和"游戏提出的问题"提供的多个备选答案。

它的作用是**强行把玩家拉进世界**：碰到选项时不操作，游戏就不往下走
（限时自动选择是特例）。玩家因此从观众变成有能动力的主人公。

**局限也要认清**：玩家的自由建立在设计师划定的范围里。哪怕 CRPG 把选项做到极多，
边界依然存在。设计选项就是在设计这个边界看起来有多自然。

## 三类选项

| 类型 | 作用 | 风险 |
|------|------|------|
| **与故事发展相关** | 影响后续细节、路线、结局 | 分支数量爆炸，工作量失控 |
| **与参数相关** | 改数值，或用参数判定走向（好感度/阵营值/flag） | 玩家看不见数值时会觉得选了没用 |
| **无意义选项** | 活跃气氛、放缓节奏 | 用多了玩家会过度解读选项，之后发现无影响会反感 |

无意义选项不是不能用，是**不能让玩家意识到它无意义**。

## 两条铁则

### 铁则一：设计没有破绽的选项

玩家绝不该产生"为什么我不能这么做？"的念头。

典型破绽：**不存在的选项**——面前摆着三个物品，选项只给两个，第三个不可交互。
玩家会认定这是设计缺陷而不是设计意图。

### 铁则二：不要给玩家压力

不该出现的玩家心理活动：
- "这选项有意义吗？"
- "我到底该怎么选？"（缺乏判断依据）
- "这些选项是什么东西？"（看不懂）

## 设计要点

### 1 明确选择的基础

玩家必须知道**不同选项的差异依据是什么**。

```
"和朋友走路上学"  vs  "坐私家车上学"
判断基础：交通工具不同 + 同行者不同 → 玩家能预判后续差异
```

如果两个选项之间的"基础"传达不到，玩家会认为区分无意义。

### 2 选项之间要有真实差异

语义相近、指向相近的选项 = 无意义选项。

```
❌ A「我知道了」 / B「明白了」
✅ A「我知道了」（沉默接受） / B「我不接受」（当场反驳）
```

### 3 结果要有必然性

玩家做选择时是带着预期的。结果与预期相反不是不行，但**必须给合理的发展过程**，
否则玩家会认为策划在耍猴，直接失去动力。

## 出现时机

选项出现在没有必然性的地方，会破坏剧本连贯性并给玩家压力。两条定位法：

### 按结构定位

| 结构位置 | 选项的作用 |
|---------|-----------|
| 开端 → 过程 | 起决定性作用的分岔（决定路线） |
| 过程 → 高潮 | 放在高潮发生**之前**（决定以什么姿态迎接高潮） |
| 结局 | 通常不放选项 |

### 按主角情感波动定位

在**能引发情感波动的事件处**放选项。原因很实际：不同玩家在同一事件下的情感不同，
给选项可以避免主角做出违背玩家情感预期的举动（这是"出戏"的主要来源之一）。

## flag（标志）

flag = 从程序层面控制剧本流程的变量。剧本里要显式写清楚：

```
? 选项组 (id: ch2_interrogate)
  - 「逼问」        -> scene_2a   [set: threatened=1]
  - 「放下枪」      -> scene_2b   [set: trust+=1]
  - 「沉默」        -> scene_2c   (需要 flag: knows_map==1)
```

约定至少写清四件事：选项组 id、每个选项的文本、跳转目标、读写的 flag。
带前置条件的选项要标出条件，否则程序无法实现"这个选项什么时候才出现"。

## 分支管理的现实建议

| 手法 | 说明 |
|------|------|
| **收束点（bottleneck）** | 分支跑一段后汇回主干，避免分支数指数爆炸。汇回前要让不同分支留下不同 flag，用于后续差异化台词 |
| **差异体现在细节而非分支** | 同一场景用 flag 换掉几句台词，玩家的"我的选择有用"感受和真分支接近，成本差一个量级 |
| **结局用 flag 组合判定** | 结局数 = flag 组合的分类结果，而不是分支树的叶子数 |
| **多结局必须有提示** | 用"你还没看到真正的结局"式收尾告诉玩家还有内容，否则多结局等于白做 |

## 自查

- [ ] 每个选项组里，玩家能否说清"这两个选项差在哪"
- [ ] 每个选项是否都有跳转目标或 flag 写入（否则就是纯无意义选项）
- [ ] 无意义选项的占比是否够低
- [ ] 场景里可见但不可选的对象，是否有理由（或者干脆移除）
- [ ] 结局前是否有过至少一个"决定性选项"
- [ ] 前置条件选项的条件是否写清楚了
