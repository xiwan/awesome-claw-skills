# 文本：台词 / 旁白 / 指示

## 三者分工

| 成分 | 定义 | 主要功能 |
|------|------|---------|
| **台词** | 角色讲出来的话（对话 Dialogue / 独白） | 表达感情、说明情况、推进故事 |
| **旁白** | 除台词外显示在画面上的内容（风景描写、心理描写） | 阐述事实、表现心理、表现视觉与物理、表现时间、推进故事 |
| **指示** | 制作过程需要的提示（背景变化、角色登场、跳转） | 让程序和美术能执行 → `script-format.md` |

## 台词的三个功能

1. **表达感情**（最基础）——"呵""嘁""嗯"一个字就能传情绪。
   顺序永远是：角色先产生某种情感，才说出对应的话。所以任何台词都在表达感情。
2. **说明情况**——图像说不清时才用台词补。但**说明用台词不能长**，玩家耐心有限。
3. **推进故事**。

## 台词的四大病（写完先照这四条查）

以一段"原文本"为例：

```
「你从哪儿拿到的这张地图？」
「这张地图是我前几天在城外一个名叫黑死馆的别墅的座钟里偶然发现的。」
「你拿这张地图想干什么？」
「你想知道？那就把你手中另一半地图交出来。照做我就考虑告诉你。」
「我要是交出来，你就知道宝藏的埋藏地点了。你休想得逞。那些宝藏是我父亲的遗物，
绝不能落入你这等恶人之手。」
```

| 病 | 表现 | 药 |
|----|------|-----|
| **1 太长** | ① 单句字数大（最后一句要读很久）② 感觉冗长（"地图""宝藏"反复出现） | 拆句；重复词换代称或直接删 |
| **2 说明性太强** | 一句里塞了时间+地点+方式+结果（第二句） | **一句台词只传一个关键信息**，其余慢慢漏 |
| **3 缺乏动作** | 只有信息交换，没有人在动 | 台词里加动作表意（"再不说我就剁了你这手指"） |
| **4 读不出角色情感** | 谁说都一样 | 前三条改完，这条自然解决 |

改写后：

```
「举起手来！你从哪儿拿到的这张地图？」
「不知道。」
「快说！不然我可开枪了。」
「嘁……在黑死馆。」
「那里我调查过！老实回答！」
「就是在那儿，在座钟里。」
「诶……」
「喂，差不多可以把那个吓人的玩意儿放下了吧？」
「别动！你拿那张地图想怎么样？」
「……不好说。要是把剩下的半张交出来，我倒可以考虑告诉你。」
「开什么玩笑！那是我父亲的遗物，绝不交给任何人！」
「看来这地图上真的记录了宝藏的埋藏点。」
「你这混蛋！」
```

信息量没变，条数变多、每条变短，动作和情绪进来了，还多出一层"对方套话成功"的博弈。

## 关键信息放在最后

游戏文本常会自动滚动/自动播放，所以**最重要的信息尽量放在一段的末尾**，
保证玩家不会因为跳过而错过；必要时强制玩家看完关键段（视项目而定）。

## 两个土办法

- **出声朗读**：把自己代入角色读一遍。别的方法都不如这个有效。
- **捧哏与逗哏**：逗哏提供突发的喜剧效果，捧哏负责替玩家说"他刚才那句真好笑"。
  游戏里的捧哏本质是**给玩家的解释器**，缺了它笑点会掉在地上。

## 让台词不只是台词

一句话要成为"台词"，需要表情、语境、情境三个基础。缺这些，它只是角色嘴里的一句话。

| 要素 | 说明 |
|------|------|
| **表情** | 同一句台词配不同立绘表情，意思完全不同。有立绘就一定要给表情指示 |
| **感情动向** | 同一句台词在角色不同情感状态下含义不同。让角色在不同情感环境下说出**同一句台词**（类似重复蒙太奇），是低成本高效果的手法 |
| **语境** | 说话人当下的状况与状态 |
| **言外之意** | 脱离字面的信息，靠表情、语气、语境、隐含意志传达。也是"隐喻"与考究向内容的来源 |

## 用台词携带信息

在措辞、句尾、语调上做变化，一句话就能交代说话人和世界的信息。

| 维度 | 例 |
|------|-----|
| **时代** | "吾 / 尔等 / 朕"（古代） vs "我 / 你 / 他"（现代） |
| **出身** | 方言词、口音字 |
| **语言圈** | "初次见面，请多多关照"（日式） vs "亲爱的陛下，这是臣为您献上的海图"（西方中世纪） |
| **年龄** | "人家的名字叫小月啦"（幼女） vs "老朽乃谷木真人"（老者） |

**敬语是说明角色关系的最好工具**：谁对谁用敬语，上下级关系和亲疏一目了然。
故意错位使用敬语能造出特定情绪（老人对小孩："小祖宗，您可消停一会吧！"）。

## 旁白的分工

旁白负责台词说不了、画面演不出的部分：

- 行为动作：移动、调查、战斗
- 动作结果：门锁上了 / 发现了宝物 / 被敌人偷袭
- 场所与情况
- 时间流逝
- 心理描写

原则：**画面能演的不要用旁白说**。旁白是补位，不是省事的出口。

## 外观：文本在屏幕上长什么样

台词写得好但显示效果差，等于没写好。写之前必须先拿到这些技术参数：

| 参数 | 为什么要 |
|------|---------|
| 最大行数 / 每行字数 / 文本框总字数 | 决定断句和翻页点 |
| 横排 / 竖排 | 影响标点与换行 |
| 显示速度（逐字速度） | 决定"停顿"用什么实现 |
| 文字颜色 / 字号 / 加粗是否可用 | 重要台词的强调手段 |
| 暂停与换行时机 | 节奏 |
| 字体类型 | 中文字库缺字风险 |

拿到参数后，**换行与翻页点要当成剧本内容来写**，不要留给程序随机断。

## 语言规范：统一优先于正确

- 术语与表述必须统一（"增加 100% 攻击力" / "攻击力提升 100%" / "攻击力翻倍" 只能留一种）
- 常规错误照常避免：错别字、语法错误、敬语误用、全角半角混用、句尾符号不统一
- **但游戏有表现特殊性**：颜文字、"……"与"…"的美观取舍、故意的错字口癖——
  只要提升表现，规范可以让路。判断顺序是：表现效果 > 规范一致 > 语法正确
