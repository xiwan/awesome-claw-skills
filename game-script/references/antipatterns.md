# 反模式与人工审读

机械检查（`scripts/script_lint.py`）只能抓文本层面的病。这里列的是必须靠人读出来的。

## 反模式清单

### 主题与故事

| 反模式 | 症状 | 修法 |
|--------|------|------|
| **主题写在台词里** | 角色说"友情才是最强大的力量" | 删掉，改用一次选择或一个结局来说 |
| **主题里没有游戏目的** | 玩家问"所以我要干什么" | 回到主题层改，不要靠加任务补 |
| **故事与系统各说各话** | 系统让你打 Boss，剧情说要和平 | 统一口径；系统赢，剧情改 |

### 角色

| 反模式 | 症状 | 修法 |
|--------|------|------|
| **角色被挂起** | 某角色打完就再没戏，但还在场 | 给新定位，或让他死/失踪/离开 |
| **沉默角色** | "入队前强得要命，入队后弱得狗都不如" | 给独占能力、牺牲桥段、背叛变脸 |
| **好好先生伙伴** | 队友对主角言听计从 | 在关键选择处让他反对 |
| **主角个性过强** | 玩家说"这不是我会做的事" | 削个性、给选项、给定制 |
| **主角动机牵强** | 玩家跟不上主角为什么要去 | 提前给信息，或把情境铺到"换谁都会这么做" |
| **待攻克对象太多** | 玩家不知道该先追哪个 | 砍数量，或分章节释放 |
| **救星滥用** | 每次危机都有人从天而降 | 全局限量，最好只用一次 |
| **系统角色乱背刺** | 商人突然翻脸 | 一整个项目里最多用一次 |
| **家人角色放着不管** | 开头很重要，中段消失 | 家人自带存在感但衰减最快，要主动给戏 |
| **贤者亲自下场打架** | 贤者角色开始成长/变强 | 贤者是静态角色，一旦成长就失去说服力 |
| **功能重复的角色** | 两个队友定位一样 | 外观相似不算重复，定位相似才算——改定位而不是改造型 |

### 结构

| 反模式 | 症状 | 修法 |
|--------|------|------|
| **开端三件事没做完** | 不知道干什么 / 不会玩 / 不知道这是什么游戏 | 补齐目的、教程、世界与人物 |
| **前置准备写成说明文** | 前 30 分钟在读设定 | 把设定塞进事件里漏出来 |
| **过程无趣却指望高潮** | 打完 Boss 只觉得"就这样？" | 问题在过程的投入量，不在高潮的写法 |
| **提前抛结论** | 反转发生时玩家反应冷淡 | 先把玩家推到"心理饥饿"再给 |
| **高潮后拖长** | 结尾冗长、玩家开始快进 | 高潮后立刻收尾 |
| **章节全是障碍型** | 连环跑腿、重复劳动 | 混入援助型、主题型、支线型章节 |
| **支线喧宾夺主** | 玩家忘了主线是什么 | 支线要与主线相关且更短 |
| **失败没有故事解释** | 死了直接读档，世界观不圆 | 明确死亡在这个世界意味着什么 |
| **重玩惩罚过重** | 失败一次损失巨大 | 就近载入、成本归还/降低 |

### 选项

| 反模式 | 症状 | 修法 |
|--------|------|------|
| **无意义选项过多** | 玩家发现选了没影响后反感 | 控制占比，或让差异体现在几句台词上 |
| **不存在的选项** | 场景里三个东西，只能点两个 | 补上第三个，或把它从画面里移除 |
| **选项判断依据缺失** | "我该怎么选？" | 说清两个选项差在哪（工具、同伴、态度…） |
| **结果违背预期又不解释** | 玩家觉得策划在耍猴 | 给合理的发展过程 |
| **选项出现时机随意** | 打断叙事节奏、给玩家压力 | 放在结构分岔处或情感波动处 |
| **多结局没提示** | 玩家不知道还有别的结局 | 用"你还没看到真正的结局"式收尾 |

### 文本

| 反模式 | 症状 | 修法 |
|--------|------|------|
| **一句话交代全部** | 时间地点方式结果挤在一句 | 一句只传一个关键信息 |
| **台词无动作** | 只有信息交换 | 加动作表意词，或配表情/旁白 |
| **旁白替画面干活** | 画面演得出来的还要写一遍 | 删旁白 |
| **表述不统一** | "+100% 攻击" / "攻击翻倍" 混用 | 建术语表，全局统一 |
| **换行翻页交给程序** | 关键台词被切在页尾 | 断句和翻页点写进剧本 |
| **没给表情** | 有立绘但每条台词都是默认脸 | 每条台词都标表情 |

## 人工审读清单（机器查不出的部分）

### 一读：结构
- [ ] 开端三件事（目的/玩法/这是什么游戏）是否都完成
- [ ] 8 段期待曲线里，结论是否出现在第 6 段之后
- [ ] 高潮之前，玩家投入了什么成本（列得出来吗）
- [ ] 每个章节属于 4 种类型里的哪一种（说不出来的章节大概是废章节）

### 二读：角色
- [ ] 逐章列出每个在场角色的定位，有没有找不出定位的
- [ ] 被击败/被解决的角色，有没有立刻拿到新定位或退场
- [ ] 主角的每个行动，玩家能不能理解动机
- [ ] 有没有两个角色定位重复

### 三读：主题
- [ ] 主题有没有被谁说出口（lint 只能查你告诉它的词）
- [ ] 主题是否通过至少一次选择 + 一个结局表现
- [ ] 结局是否回答了主题提出的问题

### 四读：出声朗读
- [ ] 把每个角色的台词读出来，能不能听出是谁在说
- [ ] 有没有哪句读起来喘不上气（就是太长）
- [ ] 有没有哪句读起来没有情绪

### 五读：可执行性
- [ ] 程序能不能不问你就实现所有跳转和 flag
- [ ] 美术能不能不猜就知道要画什么背景、什么表情
- [ ] 音频知道每处 BGM/SE 切换点吗
- [ ] 本地化知道哪些是变量、字数上限多少吗

## 评审别人的剧本时的提问顺序

1. 这个游戏的主题是什么？（说不出一个词或一句话 → 主题没定）
2. 玩家在开端 5 分钟内知道要干什么吗？
3. 高潮前玩家投入了什么？
4. 第 3 章里，X 角色的定位是什么？（随机抽查角色）
5. 这组选项的判断依据是什么？（随机抽查选项）
6. 这句台词里，你最想让玩家记住哪个信息？（随机抽查长台词）

六个问题答不上来的地方，就是要改的地方。
